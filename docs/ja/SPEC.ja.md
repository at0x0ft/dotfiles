# home-manager 構成 要件定義書

## 1. 要件定義

1. Linux (x86_64 & arm64; WSL を含む) と Darwin へのツールインストールを、大部分の共通化された宣言的コードで管理すること
2. ログインシェルはここでは管理しない
    1. ログインシェルの選択は OS 固有の問題であり、home-manager がそれに依存することは避けたい
    2. 現状では zsh を前提とするが、bash や fish 等でも機能するよう設計すること
3. 環境ごとに差分がある場合、base と override の層構造でアプリケーションを柔軟に切り替えられる機構を持つこと
4. ツールの設定ファイルは home-manager と疎結合に保ち、従来の shell-script 製 dotfiles としても管理可能な形式にすること
5. ツール間の依存関係を解決するような高度な共通モジュールは作らず、読み込み順制御のみをサポートすること
6. シェルのプラグインマネージャー (例: zinit) はプラグインの読み込みにのみ使用し、バージョン管理は home-manager が担うこと

---

## 2. 設計原則

1. **home-manager の役割限定**: home-manager は「パッケージ管理」と「ファイル配置」に徹する。ツール設定は素のシェルスクリプト / 標準形式で記述し、`programs.*` による設定生成は使わない。生成してよいのはローダー (`hook.sh`) と RC エントリポイント (`.zshrc`) に限る
2. **パッケージ管理と設定の分離**: パッケージインストール (`home.packages`) と設定ファイルの配置 (`config/`) は別の関心事とする。Nix はバージョンを厳密に管理し、設定ファイルはポータブルかつ Nix 非依存の形式を保つ
3. **クロスプラットフォーム共通化**: Linux / Darwin の差異は `flake.nix` の system パラメータとプラットフォームモジュールで吸収し、`home.nix` とシェルスクリプト群は最大限共通で使う
4. **環境別オーバーライド**: base となるパッケージ/設定セットの上に、環境固有の差分を `imports` 機構で重ねる
5. **ログインシェル非依存**: ログインシェルの管理は対象外とする。登録したスクリプトのシェル互換性は登録側のモジュールの責務とする
6. **読み込み順制御のみ**: `shell-hook` はフェーズと優先度による読み込み順の制御のみを担い、ツール間の依存解決やツール固有のロジックは持たない
7. **明示登録・自動読み込みなし**: `config/` は人間が読みやすいよう整理されているだけで、自動読み込みはされない。フックスクリプトは Nix モジュールに明示的に登録しなければならない。`shell-hook` はディレクトリ構造やファイル拡張子から読み込み挙動を推論してはならない
8. **ファイル配置の規則**: XDG 準拠のアプリ設定 (`~/.config/` 以下) には `xdg.configFile` を使う。ホームルートのファイル (`.zshrc` 等) には `home.file` を使う。`mkOutOfStoreSymlink` は使わない
